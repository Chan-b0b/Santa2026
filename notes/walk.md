# walk: 값 집합 걷기

작성: 2026-11-26. 코드 `solvers/walk/` (walk.cpp 엔진, bench.py 비교 실행기, table.py 표), 결과 `results/walk.csv`, 진행 상황 [walk.status.md](walk.status.md).

## 1. 만든 것

상태는 값의 집합 V다(시작값 S와 목표값 T가 늘 들어 있다). 비용은 |V \ S|. 조리법은 상태에 들어 있지 않다.

| 부품 | 구현 |
|---|---|
| 값 -> 칸 | 선형 탐사 해시(지우기 지원). 칸 번호가 비트셋 자리다. 칸 0은 "유도됨" 표시용으로 비워 둔다 |
| 조리법 목록 | 값마다 V 안의 모든 (a, b, 연산) 가운데 결과가 그 값인 것. 값을 넣을 때 O(|V|) 해시 조회로 새 조리법(그 값을 만드는 것, 그 값을 재료로 쓰는 것)을 더하고, 지울 때 그 값이 든 조리법을 뺀다. 역색인 `users` |
| 쌍 표 | V의 모든 순서 없는 쌍(같은 값 둘 포함)의 합, 차, 곱, 몫(나누어떨어질 때) -> 관계 수. 넣고 뺄 때 O(|V|)로 갱신. V에 없고 관계 수가 `minrel`(기본 2) 이상인 값이 후보 목록(무작위로 뽑을 수 있게 배열 + 자리 색인) |
| 닫힘과 삭제 판정 | rosswade 정리 5. 값마다 비트셋 rho(v)(비트 x = x 없이 v를 유도할 수 있음). 시작값은 전부 1, 나머지는 `allow(v) AND OR_조리법(rho(a) AND rho(b))`의 최소 고정점을 작업 목록으로 계산. x를 지울 수 있다 <=> 모든 목표 t에서 rho(t)의 비트 x가 1. 값을 넣을 때는 이어서(단조 증가) 계산하고, 지운 뒤에는 처음부터 다시 계산한다 |
| 이동 | 후보 w를 뽑아 넣는다 -> w를 보호한 채, 지울 수 있는 값 x를 무작위로 하나 골라 x와 "x 없이는 유도되지 않는 값"을 지우고 다시 판정, 없을 때까지 되풀이 -> 하나라도 지웠으면 보호를 풀고 한 번 더(w 자신도 필요 없으면 지움) |
| 채택 | 크기가 늘지 않으면 받는다. 늘면(아무것도 못 지움) 확률 pu로 받는다. pu는 실행 시간에 따라 pu0=0.02에서 pu1=0.0005로 기하 감소 |
| 레지스터 | (설계와 다름, 아래 2절) 값이 바뀐 상태마다 순서를 만들어 48칸에 들어가는지 보고, 넘치면 이동을 되돌린다 |
| 프로그램으로 되돌리기 | 우선순위 목록 스케줄(직전 순서를 우선순위로, 조리법은 그때 고름: 직전 조리법이 쓸 수 있으면 그것, 아니면 가장 최근 재료) -> 목표에서 닿지 않는 값 제거 -> 순서를 고정하고 재료 수명을 덜 늘리는 조리법으로 바꾸기(2회) -> 레지스터 배정. 넘치면 우선순위를 가우스 잡음으로 흔드는 수리(`repair`회) |
| 최선 기록 | 크기가 지금까지 만든 프로그램보다 작은 상태에서만 컴파일해 보고, 48칸 배정이 되는 프로그램이 실제로 만들어졌을 때만 기록한다. 실행기(bench.py)가 다시 `check_program`으로 검사한다 |

## 2. 설계와 다르게 한 것

- **레지스터(1회차만 설계와 다름, 2회차와 지금 기본값은 설계대로).** 설계는 "안 맞는 상태에서도 걷기는 계속할 수 있다"였다. 처음 시험에서 큰 무작위형(scored_0051, 290)이 바뀐 상태 1,000개(약 1초) 뒤에 필요한 레지스터가 69~79개가 됐고(48 한도), 그때 찾은 289짜리 집합은 208번 모두 컴파일에 실패했다. 그래서 1회차는 값이 바뀐 상태마다(전체 이동의 약 7%) 순서 만들기를 한 번 돌려 넘침이 있으면 이동을 되돌리는 방식(`reg=1`)으로 쟀다. 되돌리기는 지운 값을 같은 칸에 다시 넣고 rho를 저장본으로 돌린다. 이 방식은 더 작은 집합을 하나도 못 봐서, 2회차는 설계대로 레지스터를 안 보고 걷고(`reg=0`) 최선보다 작은 상태에서만 컴파일을 시도했다. 지금 기본값은 `reg=0`.
- **새 값의 자리.** 지운 값이 있으면 새 값 w의 우선순위를 지운 값들 가운데 가장 이른 것으로 둔다(w가 지운 값의 역할을 이어받는 경우가 대부분이라서). 지운 값이 없으면 재료 가운데 늦은 것 바로 뒤.
- **보호.** 넣은 직후의 w는 늘 "필요 없는 값"이라 보호하지 않으면 바로 지워진다. 그래서 첫 삭제 전까지 w를 보호한다. 성장으로 받은 w는 다음 이동에서 보통의 값이 된다(그 이동에서 새 값과 함께 쓰이면 남고, 아니면 지워진다).
- 최선으로 돌아가기(`back`)는 넣었지만 기본은 끔.

## 3. 검증

- 단순 구현 대조(`check=N`: N번 이동마다): 조리법 목록을 모든 쌍 완전 탐색과, 쌍 표와 후보 목록을 처음부터 다시 센 것과, rho의 모든 비트를 "x를 뺀 V에서 모든 쌍을 되풀이하는 닫힘"과 비교. 작은 퍼즐 10개(길이 22~64)에서 8초씩 약 7만 회 대조, 되돌리기 경로만 쓰게 한 실행(`rslack=-1`)에서 약 1.3만 회 대조, 불일치 0.
- 출력은 모두 bench.py가 `check_program`으로 검사한다.

## 5. 판단

1단계 기준(30개 합으로 대조군 + 5 이상, 또는 큰 무작위형에서 대조군 0일 때 걷기 3 이상)을 넘지 못했다. 2단계는 하지 않았다.

- reg=1: 1 / 1 대 lns 4 / 5. reg=0: 5 / 5 대 4 / 5. 큰 무작위형은 2 대 1로 조금 낫지만 표본 10개에서 차이 1이다.
- 왜 안 되는가(숫자):
  1. 이동 속도는 문제가 아니다. 120초에 큰 무작위형도 240만 번 이동, 같은 크기 이동을 수만~십수만 번 받는다.
  2. 평지가 좁다. 걷기가 출발 집합에서 벗어난 값은 평균 큰 무작위형 29개(값의 약 11%), 무작위형 17개, 구조형 10개이고 최대도 36/23/17개다. 더 작은 집합은 30개 중 4개 퍼즐에서만 나왔고, 씨 1, 2와 300초 모두 같은 퍼즐의 같은 크기였다. 시간과 씨를 늘려도 새 출구가 안 생긴다.
  3. 레지스터가 출구의 절반을 막는다. 걷기 중에 48칸을 지키면(reg=1) 출구를 하나도 못 본다(바뀐 상태의 27%를 되돌림). 지키지 않으면 출구 4개 중 2개가 넘침 합 126~220이라 수리로도, 넘침을 줄이는 걷기(reg=2)로도 못 맞췄다.
- 쓸모 있는 부산물: 걷기 전 삭제 판정(knockout)만으로 1,000개에서 8개 -8을 5초에 얻었다. lns의 이동 2가 못 보던 것이다. 다른 접근법이 best를 바꿀 때마다 한 번씩 돌릴 가치가 있다(명령은 6절).

### knockout만(걷기 0초) 1,000개

- best의 모든 프로그램에서 처음 삭제 판정만: 5초. 지울 수 있는 값이 있는 퍼즐 10개(indep 4, mixed 4, 구조형 2), 7개는 48칸 배정 성공해 각 -1(0017 0042 0334 0420 0480 0756 0839) + 30개 묶음의 0313.
- 실패 3개(0262, 0321, 0682): 값 하나를 지운 순간 넘침 합 251 등, 수리 3만 회로 18~26까지만.
- lns의 이동 2(`tryElim`)는 삭제를 탐색으로 확인하는 방식이라 이 값들을 못 봤다(채택 0). 이 값들은 다른 조리법이 이미 V 안에 있어서 탐색 없이 지울 수 있는 것들이다.

## 6. 실행

```bash
g++ -O2 -march=native -std=c++17 -o solvers/walk/walk solvers/walk/walk.cpp
# knockout만 1,000개 (약 5초, best 보다 짧은 것만 results/walk.csv 에)
.venv/bin/python -I -u solvers/walk/bench.py --bin solvers/walk/walk --ids solvers/walk/all.txt --secs 0 --seeds 1 --procs 2 --tag knock --out solvers/walk/knock.jsonl --save
# 걷기 비교
.venv/bin/python -I -u solvers/walk/bench.py --bin solvers/walk/walk --src solvers/walk/src30.csv --ids solvers/walk/set30.txt --secs 120 --seeds 1,2 --procs 5 --tag walkr0 --out solvers/walk/bench_walkr0.jsonl --save
.venv/bin/python -I solvers/walk/table.py solvers/walk/bench_walkr0.jsonl solvers/walk/bench_lns.jsonl
```

설정(`--opts`, 지금 기본값): `pu0=0.02 pu1=0.0005 minrel=2 reg=0 rslack=0 place=1 repair=2000 rmode=0 hold=0 back=0 cshare=0.3`. `reg=1`은 1회차 방식, `reg=2`는 작은 상태에서 넘침 하강, `rmode=1`은 창 이동 수리, `hold=H`는 성장한 값을 H번 이동 동안 지킴(측정 안 함). 진단용 `check=N probe=N trace=1|2`. 1회차 실행 파일의 소스는 `walk_v1.cpp`, 2회차 실행 파일은 `walk_r0`.
