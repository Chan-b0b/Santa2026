## 해 봤지만 효과가 없던 것

- 목표값 하나만 떼어 "첫 사용 직전"에서 다시 유도(`lns.py`): 0.4%.
- 탐색 폭 확대, 2명령 끝점 표(F2): 풀이 같으면 0.5% 미만.
- 시작값만으로 짧은 식 찾기(`closure.py`, `control.py`): 실제 목표값과 같은 크기 난수의 분해 크기가 같다. 목표값 하나하나에는 시작값 기준 구조가 없다.
- 같은 비용 이동을 레지스터 압박이 늘지 않을 때만 받기: 2.98% → 1.43%로 나빠짐. 같은 비용 이동의 다양성이 중요하다.
- 같은 비용 이동에서 작은 값이 늘어나는 쪽 선호(`bias`): 차이 없거나 나빠짐.
- 허브 투표(`exp_hub.py`: 여러 목표값이 명령 1~2개로 닿는 새 값 찾기): 순환 유도를 제대로 막으면 예상 이득 0.
- 매끄러운 수로 허브 찾기(`exp_factors.py`): 구조형 퍼즐은 값이 작아 후보의 35~42%가 매끄러워서 구분이 안 된다.
- ruin 크기를 20, 32로 키우기: 12보다 나쁨(1.4~1.5% 대 2.1%).
- ruin 대상 고르기를 "이웃을 따라 자라는 덩어리"(1.59%)나 "아무 노드"(1.41%)로 바꾸기: 지금 방식(한 노드의 바로 이웃, 2.07%)보다 나쁨.
- ruin 에서 다시 만드는 순서를 무작위(1.51%)나 큰 값부터(0.92%)로 바꾸기: 작은 값부터(2.07%)보다 나쁨.
- 조금 나빠지는 ruin 이동을 낮은 확률로 허용(`pup`): 차이 없음(1.4~1.8%, 잡음 범위).
- 퍼즐당 시간을 20초에서 60초로 늘리기: 2.07% 대 2.15%. 개선은 처음 30초 안에 거의 다 나온다.
- 같은 결과에서 씨만 바꿔 이어 돌리기(2회차): 퍼즐당 0.3개 수준.
- 레지스터 인식 탐색(`aware`: 수명을 늘려도 48개를 넘지 않는 값만 재료로 허용): 무작위형 19개 퍼즐 × 30초에서 0.1~0.3%로 차이 없음. 무작위형 퍼즐은 이 방식으로는 거의 줄지 않는다.
- 최선 상태로 돌아가 크게 허문 뒤 다시 줄이기(`kick=3~6 kickk=12~40 kickslack=3~10`): 25개 퍼즐에서 차이 없음. 일반 이동만으로도 30초에 0.03~0.08%뿐이라 이 퍼즐들은 지금 이동 종류로는 포화다.
- chain 솔버를 다른 설정(digits, alpha)으로 새로 구성해 재합성: 25개 퍼즐 모두 지금의 최선보다 길다(예: 구성 151 → 재합성 135, 최선 106). 지금의 최선은 quirk 의 숨은 정수 복원과 여러 패스가 쌓인 결과라 새 구성 한 번으로는 못 따라온다.
- 초반 노드를 모든 식 모양으로 완전 탐색(`exp_boot.py`): 재합성을 거친 프로그램은 초반 노드가 전부 여러 곳에서 쓰이는 명령 1개짜리라 다시 만들 대상이 없다.
- ruin 안에서 새 중간값을 값 표에 바로 넣어 뒤의 노드가 재료로 쓰게 하기: 구조형 25개(0.30%, 0.19% 대 0.14%, 0.27%), 무작위형 19개(0.46% 대 0.46%)에서 차이 없음.
- 다른 접근법의 프로그램에서 유도식을 가져와 탐색에 섞기(ALT): 이미 여러 출발점을 거친 best 에서는 0.19% 대 0.24%로 차이 없음. 코드는 뺐다.
- 같은 계산량에서 "1씨 × 21초"(1.69%), "3씨 × 7초"(1.71%), "7씨 × 3초"(1.51%)는 비슷하다. 계산량을 3배로 한 "9씨 × 7초"가 2.10%. 씨를 늘리면 천천히 더 줄어든다.
