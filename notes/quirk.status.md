## 핵심 발견 (2026-11-24)

- 구조형 퍼즐(multiplicative, shared, mixed 앞쪽 절반)의 목표값은 `t = k·a·b + r` 꼴이다. a, b 는 퍼즐마다 숨어 있는 정수 몇 개(18~22비트가 많다), k 와 r 은 작다. r 이 `k2·r1 + r2` 처럼 겹친 것도 있다.
  - 근거: 공개 조사 노트(`research_notes/.../competition_intelligence.md` 116행)의 scored_0006 사례를 직접 확인했다. 숨은 정수 261389, 327190, 571027, 835418 로 32개 목표가 전부 설명된다.
- `solvers/quirk/decode.py`(+ C++ `basescan`)가 이 정수들을 1.6초에 복원한다: d 를 2^24 까지 전부 훑어 `|t mod± d|` 가 작은 목표 수를 세고, 같은 `(t, r)` 에서 `d·d' | t − r` 인 쌍만 남긴 뒤 탐욕 선택.
- 복원한 정수를 relate 솔버의 `seeds` 로 넣으면 scored_0006 이 한 번 실행으로 163 → 126 (그때 best 는 144, 공개 해는 112).
- 무작위형(independent) 퍼즐은 구조가 없다. 레지스터 48개에서 고르는 사슬은 명령당 약 8비트가 한계라 60비트 목표는 8개 안팎이 바닥이다(지금 9.3). 여기는 quirk 대상이 아니다.

## 파일

- `solvers/quirk/decode.py` + `basescan.cpp`: 엄격한 1차 해독 (d ≤ 2^24 전수 훑기, 쌍 검증).
- `decode2.py`: 1차 결과 확장 (2^24 넘는 근사 제곱, 몫의 공약수로 새 정수, 허브 크기에 비례한 느슨한 설명).
- `decode3.py` + `pairscan.cpp`: 작은 정수(2^8~2^20)용. `(t, k, a, b, r)` 를 전부 모아 서로 받쳐 주는 정수만 남긴다. practice_0026 에서 4765, 6508, 1300, 3463 복원(0.15초).
- `decode_any.py`: decode2 + decode3 합집합. `decode_all.py`: 전체 퍼즐 일괄 실행. `decode_practice.py`: 가족별 적용 범위.
- `decode4.py` + `basescan2.cpp`: 1차가 빈손일 때 쓰는 완화 훑기. `decode5.py`: 짝이 후보가 아닐 때 몫의 공약수로 허브를 찾는 실험(아직 안 씀).
- `run2.py`: 해독한 정수를 relate(`solver3.solve_once` 의 `seeds`)와 chain(`chain_seed.py` 가 `Machine.seed_bases` 를 바꿔 끼움) 두 솔버의 씨앗으로 넣어 풀고, 엔진별 최단을 lns 재합성기 사본으로 다듬어 최단을 `results/quirk.csv` 에 쓴다. `run.py` 는 relate 만 쓰는 1판.
- `polish.py`: quirk 결과를 lns 재합성기 사본(`elf_lns_snap`, 15:42 에 `solvers/lns/elf_lns` 를 복사)으로 다듬는다.
- `msbatch.py`: 다중 출발. 퍼즐마다 `results/*.csv` 와 best 의 프로그램을 각각 출발점으로 재합성해 best 보다 짧으면 저장.
- `small.py`: 시작값에서의 트리 비용 닫힘과 가운데서 만나기로 작은 수의 최단 식 찾기.
- `cf.py`, `attrib.py`, `show.py`, `forensic.py`, `nt.py`: 분석 도구.

## 해 봤지만 효과가 없던 것

- 연분수로 목표 쌍의 `q·t1 − p·t2 = r` 찾기: 같은 허브(a·b 가 같음)는 잡지만 a 만 공유하는 쌍은 못 잡는다. 공개 쪽도 이득 0이라고 보고했다. 해독기의 보조 수단으로만 둔다.
- 얕은 닫힘 값으로 `t = k·h + e` 허브 투표(`forensic.py`): 작은 h 에서 우연 일치가 너무 많다.
- `value_limit` 이 최대 목표와 가까운 것은 10^18 상한 때문이고 숨은 구조와 무관하다.
- 무작위 목표를 풀에서 하나씩 정확히 최소 비용으로 만들기(`oracle.cpp`): 지금 해가 공유 덕에 이미 더 짧다(위 16:33).
- 작은 정수 해독에서 허용폭 키우기(k ≤ 32, |r| ≤ 512): 2,000 이하 정수가 우연히 다 살아남는다. `decode6.py` 는 그래프 무게로 고르지만 practice_0148 에서 정수 2개만 확실히 잡는다.
- 허브 하나짜리 군집의 허브를 씨앗으로(`decode7.py`, 연분수 군집 + 오프셋 비트 합 최소 허브): scored_0823 등 6개 퍼즐에서 best 보다 7~28개 김. lns 가 같은 퍼즐을 30분 사이 163 → 135 로 줄였다.
- 해독 퍼즐을 씨앗과 설정을 바꿔 처음부터 다시 구성(`run5.py`): 원본 144 → 다듬어 122, 이미 다듬어진 best 116 을 못 넘는다.
- multiplicative 형에서 목표별 정확한 최소 비용(`oracle_exp2.py scored_0199`): 평균 약 4.1 인데 프로그램은 2.86. 무작위형과 같은 결론.
