## 1. 핵심 아이디어

목표값을 "지금 레지스터에 있는 값(풀)에서 몇 개의 명령으로 유도되는가"로 보고, 가장 싸게 유도되는 목표값부터 만든다.
유도 관계는 세 층으로 찾는다.

1. **직접 관계 (명령 1~3개, MITM).** 풀 값 둘의 연산 한 번으로 나오는 값 전체를 `L1`이라 하면
   `t ∈ L1`(1개), `t = L1값 op 풀값`(2개), `t = L1값 op L1값`(3개)을 찾는다.
   풀에 값이 하나 들어올 때마다 새로 생긴 L1 값 x에 대해서만 남은 목표값 t마다 `t-x, x-t, t+x, t/x, x/t, t*x`가
   풀/L1에 있는지 사전(dict) 조회한다. 증분 처리라 전체를 다시 계산하지 않는다 (`Solver.scan`).
2. **아핀 관계 (`t = k*x + e`, `t = (x+a)*k + b`, `t = (x-e)/k`, `t = (x-b)/k - a`).** x는 풀 값 또는 L1 값이다.
   `t mod x`(또는 `x mod t`)가 0 근처이면 후보로 저장하고, k와 e(또는 a, b)가 "싼 작은 수"인지로 비용을 매긴다.
   싼 작은 수는 비용표로 판정한다: 풀 값 0, L1 값 1, `A2`(= 작은 풀 값끼리의 L1 값 op 작은 풀 값) 2.
   작은 값들이 한 번 만들어지면 풀에 남아 다음부터 비용 0이 되므로, 보정값(25, 45 같은 수)이 저절로 공유된다.
   `(x+a)*k + b` 꼴은 숨은 허브 h = x+a 를 중간값으로 만들어 풀에 남기므로, 같은 군집의 다음 목표값은 `k*h + e` 2개 명령으로 끝난다.
3. **범용 구성 (관계가 없는 목표값, 군집의 첫 값, 무작위 목표값).** 비용 순서 역방향 탐색 `generic2` (3절).

매 단계에서 남은 목표값 전부에 대해 min(관계 비용, 범용 비용)을 재서 가장 싼 것을 만든다 (cheapest-first).
명령 3개 이하의 관계가 있으면 범용 탐색을 건너뛰고 바로 만든다.

## 2. 데이터에서 확인한 구조

- **independent**: 목표값이 한 자릿수 구간(예: 1e14~1e15)의 균등 난수다. 시작값 진법으로 전개해도 자릿수가 무작위다.
  목표값 사이 관계는 없다. 풀의 작은 값 품질과 레지스터 사용이 전부다.
- **shared**: 숨은 허브 h가 있고 목표값은 `k*h + e` 꼴이다. practice_0004 의 예:
  h = 59021856 = 669 × 88224 = (9+30×22) × 32×(5+32×(5+9×9)) 이고 목표값은 h+25, h+243, 2h+45, 15h+45, 22h+25.
  다른 허브 10974276 = 669 × 16404 도 인수 669 를 공유한다. 즉 허브는 "시작값의 짧은 식" 둘의 곱이고, 허브끼리 인수를 공유한다.
  연습 퍼즐 shared 목표값 1,428개 중 다른 목표값/시작값에서 명령 1~2개로 바로 나오는 것은 21개(1.5%)뿐이지만,
  `k*x+e` (x 는 다른 목표값이나 그 둘의 연산 한 번, k 와 |e| ≤ 5000) 관계는 651개(46%)에 있다.
- **multiplicative**: 목표값이 작고(대부분 2^30 이하) 공통 소인수를 가진다. 관계/범용 탐색 모두 싸게 풀린다.
- **mixed**: 앞쪽 절반은 shared/multiplicative 같은 구조, 뒤쪽 절반은 independent 같은 난수(최대 60비트)다.
- **tiny**: `value_limit` ≤ 40 이면 값 집합 비트마스크 BFS 로 최적해를 구한다 (`tiny.py`).
- 추정: 숨은 프로그램 자체가 목표값당 명령 3~5개쯤을 쓰는 것으로 보인다 (practice_0004 에서 보정값과 곱수가 각각 명령 1~2개짜리 식이었다).
  확인한 것은 퍼즐 두 개(practice_0004, 0006)뿐이다. shared 에서 목표값당 2 이하로 내려가는 지름길은 못 찾았다.

## 3. 솔버 구조 (가져다 쓸 때 필요한 것)

- **SSA + 사후 레지스터 배정.** 값 하나 = 명령 하나로 기록하고(`vals`, `defs`), 끝에서 죽은 코드를 지운 뒤
  마지막 사용 시점으로 레지스터를 배정한다 (`finish`). 다시 쓰이지 않는 값은 레지스터를 차지하지 않으므로
  "보존하는 값"을 48개보다 많이 둘 수 있다. 이게 생각보다 크다 (5절).
- **풀과 표.**
  - `pool`: 값 → SSA 번호. `C`: 값 → 0(풀) 또는 1(L1). `L1`: 값 → (op, a, b).
  - `plist`: 핵심 값(시작값, 목표값, 2^20 이하의 작은 값, 관계 유도의 중간값). L1 은 plist 끼리만 짝짓는다.
  - `Q`: 작은 핵심 값 최대 40개. `A2[값] = L1Q 피연산자` 는 dict comprehension 으로 한 번에 갱신한다 (값 하나 추가에 수 ms).
  - 범용 구성의 큰 중간값은 임시값이라 plist 에 넣지 않는다.
- **보존 한도 `cap`.** plist 크기가 cap 을 넘으면 Q 밖의 값 중 가장 오래 안 쓴 것을 버린다(LRU, 버릴 때 그 값을 쓰는 L1 항목도 지운다).
  cap 은 큰 값부터 시도한다: 구조형 퍼즐은 (무제한, 72, 62, 54, 46, 38, 30), 난수가 많은 퍼즐은 (72 또는 66, ...).
  5번 유도마다 `finish()` 를 돌려 이미 48개를 넘었으면 즉시 포기하고 다음 cap 으로 넘어간다.
- **범용 구성 `generic2(t)`.** 비용 g 순서로 상태(만들어야 할 수)를 펼치는 균일 비용 탐색이다. 비용 단계마다 가장 작은 값 W2 개만 펼친다.
  - H: `v = c*m + d`. m 은 풀 값. d 는 `v ≡ d (mod m)` 인 풀 값이면 +2, L1 값이면 +3, A2 값이면 +4, 0 이면 +1. 음수 d 도 쓴다.
  - N3: `v = m*k ± c`. k 가 싼 값이고 나머지 c 가 v 의 1/8 미만일 때. c 가 다음 상태.
  - N1: `v = x ± c`. x 는 v 에 가장 가까운 풀/L1 값. N2: `v = x*q ± c`. x 는 v/q 에 가장 가까운 풀/L1 값.
  - 끝: 풀(0), L1(1), A2 또는 `L1값 op 풀값`(2).
  - 맨 위 상태에서는 L1 값(2^13 이하)도 곱수로 쓴다.
- **씨앗 what-if (`seeds2.py`).** `gcd(t_i - e_i, t_j - e_j)` (e 는 0, ±시작값, ±시작값 한 번 연산) 중 2^9 이상인 값과,
  그 gcd 들의 중간 크기 소인수(61 이상, 3개 이상 목표값에 걸친 것)를 후보로 뽑는다.
  후보를 하나씩 "먼저 만들어 풀에 넣고" 전체를 다시 풀어, 프로그램이 짧아지면 채택한다.
  practice_0004 에서 919(= 허브들의 공통 소인수)가 1순위로 나온다.
- **재시작.** 남은 시간에는 동점 처리를 무작위로 바꾸거나 설정(W2, Q 크기)을 바꿔 다시 풀고 최단을 남긴다.

## 6. 안 통한 것

- **허브를 정확히 찾아 먼저 만들기.** 허브 h 를 직접 만들면 h 의 자연스러운 분해(669 × 88224)가 8~10개 명령이라
  군집 첫 목표값을 범용으로 만드는 것과 비용이 같다. 이득은 인수를 다른 군집과 공유할 때만 생기고, 그건 씨앗 what-if 로 일부만 잡힌다.
- **설계한 작은 값 풀.** practice_0005 (목표값 37~40비트 32개)에서 50~1200 범위의 값 40개를 미리 만들어 두면 목표값당 비용이 약 7 로 내려가지만
  (32개 중 4개는 그 방식으로 못 만듦), 풀을 만드는 40개 명령이 이득을 상쇄한다. 독립 퍼즐 4개에 씨앗으로 넣어 본 결과도 기준과 같거나 나빴다.
  범용 구성이 쓰고 남긴 나머지 값들이 저절로 풀이 되는 쪽이 낫다.
- **빔 폭 키우기.** W2 6 → 12 → 32 는 0.5% 안팎이고 시간만 는다.
- **목표값 쌍의 직접 연산.** 0.3% 뿐이라 관계의 주력이 못 된다. 반드시 작은 보정값 비용표와 묶어야 한다.
- **무작위 목표값의 정보량 한계.** 풀 n≈40 일 때 Horner 계열은 명령당 5~6비트라 60비트 목표값은 9~11개가 든다. 이 아래로는 못 내렸다.

## 7. 다음에 해 볼 것

1. **정확한 수명 기반 퇴출.** 지금은 cap 을 내려가며 통째로 다시 푼다. 명령마다 "그 시점에 걸쳐 사는 값 수"를 유지하면
   어떤 값을 다시 쓸 수 있는지 정확히 알 수 있어 재시도 없이 최대한 많이 보존할 수 있다 (A2 가 Q 값에 의존하는 점을 풀어야 한다).
2. **chain 의 범용 탐색과 결합.** chain 은 폭 48 빔에 F2 표(L1 op 풀 전체)를 쓰고 independent 에서 더 짧다.
   relate 의 관계 단계(명령 ≤ 3 즉시 채택, 아핀 후보)를 chain 의 탐색 앞에 붙이는 것이 가장 쉬운 결합이다.
3. **허브 인수 공유.** `t - e` 를 싼 값(L1, A2)으로 나눠 보는 약수 채굴로 669, 919 같은 공통 인수를 찾고, what-if 로 검증한다.
   지금은 gcd 로만 찾아서 목표값 둘 이상이 "정확한 배수 + 싼 보정"일 때만 잡힌다.
4. **구간 재합성.** 완성된 프로그램에서 한 번만 쓰인 중간값 사슬을 지우고 그 목표값만 최종 풀 전체로 다시 유도한다.
5. 퍼즐당 시간 예산을 늘린 재실행 (난수 씨와 설정을 바꿔 여러 번 돌려 퍼즐별 최단을 모은다. `RELATE_CFG` 의 `rseed0`).

### 9.4 새 해독기 `hubs.py`

`k2·(k1·a·b + r1)` 꼴의 밑수 a, b 를 찾는다. 퍼즐당 0.05~0.25초 (PyPy).

1. **몫 만들기.** 목표값 t 를 2^17 이하의 약수 k2 로 정확히 나눈 몫 u 를 최대 32개 둔다. 끝 연산이 곱셈인 겹친 꼴이 벗겨진다.
2. **후보.** (가) 근사 제곱: `|u − k1·s²| ≤ k1·s/16` (k1 ≤ 64) 인 s. (나) 목표값 쌍의 gcd 를 4,096 이하의 약수로 나눈 값. 각각 상위 70개.
3. **허브 판정.** 어떤 몫 u 가 `a·b` 의 배수에서 `min(a,b)/6` 이내이고 `a·b / 2^16` 이내이면 (t, a, b) 를 설명으로 센다. 밑수 하나를 1 바꾼 것보다 작은 보정만 인정하므로 우연 확률이 쌍당 2^-14 수준이다. 배수의 곱수 k1 에는 제한이 없다.
4. **가지치기.** 서로 다른 목표 3개 이상에서 살아 있는 짝과 함께 설명에 쓰인 정수만 남긴다 (반복).
5. **확장.** 남은 정수 a 마다 `round(u/(k1·a))` (k1 ≤ 32) 에 목표 단위로 투표하고, 3표 이상인 값을 후보에 넣어 3~4 를 다시 한다 (최대 3회).
6. **정리.** 유리수 배 관계(p/q, p, q ≤ 64)인 정수 묶음에서 설명 목표가 가장 많은 것을 대표로 고른다. 설명 범위가 가장 넓은 쌍에서 시작해, 새로 설명하는 목표가 2개 이상인 정수를 탐욕으로 더한다 (최대 8개). `alt` 는 같은 묶음에서 설명 수가 2 이내인 가장 큰 정수다.

단계별 기준:

| 단 | 조건 | 연습 200개에서 해독 | 채점 1,000개에서 해독 |
|---|---|---|---|
| 1단 (`bases_scored.json`) | 지지 3개, 밑수 ≥ 1,500, 목표 ≥ 2^20, 설명 ≥ 4개 | shared 37/51, mixed 19/48, multiplicative 1/40, independent 0/45 | 305개 |
| 2단 (`bases2_scored.json`) | 지지 2개, 밑수 ≥ 600, 목표 ≥ 2^18, 설명 ≥ 5개 (1단에서 못 찾은 퍼즐만) | mixed +14, shared +5, multiplicative +4 | +110개 |

### 9.8 다음 아이디어

1. **작은 값 해독 (가장 큰 낭비, 9.7 의 표).** 설명 `(k2, k1, r1)` 에서 어휘를 복원한다: 여러 목표의 k2 로 되풀이되는 값, r1 을 `k·v ± s` 로 쪼갤 때 다른 목표가 쓰는 v 가 나오는 분해. 그다음 밑수를 `어휘·어휘 + 작은 값` 으로 설명한다 (721189 = 256·2817 + 37). search 의 `decode_smalls2` 와 보조 목표가 이미 이 방향이므로, `solvers/relate/bases_export.json` (1·2단 415개, quirk 의 `--bases` 형식) 을 search, chain, quirk 엔진에 넣어 보는 것이 가장 싸다.
2. **허브 단위 계획.** 같은 허브 P 의 목표를 `A·P + B` 의 점 (A, B) 로 보고, 어휘 한 번 연산으로 이어지는 최소 나무를 직접 짠다. 공유 중간값(P+r, k·P)을 탐색이 아니라 계획으로 만든다.
3. **가상 풀.** Q 값도 수명으로 버릴 수 있게 A2 표를 값별 색인으로 바꿔야 한다. 난수형에서 chain 과의 5% 차이가 여기서 나온다.
4. **해독 범위.** mixed 의 구조 절반은 목표가 10개 안팎이라 지지 3개 기준에 자주 못 미친다. 근사 허브 셋의 삼각 검사(`a = sqrt(H1·H2/H3)`, search 의 `tri`)를 후보 생성에 더한다.
5. **lns 와 맞물리기.** relate 가 갱신될 때마다 lns 가 `results/relate.csv` 에서 출발하는 패스를 다시 돌리면 된다. 이번에 그 패스가 chain 출발 패스보다 훨씬 많이 줄였다.

### 9.9 새 파일과 실행법

- `hubs.py` 해독기, `decode_all.py` 일괄 해독(1~3단), `explain.py` 목표별 설명 출력, `export_bases.py` 다른 접근법용 내보내기.

- `replay.py` 프로그램 재생, `show2.py` 씨앗을 넣은 유도 과정, `evalp.py` 연습 해독 퍼즐에서 설정 비교, `minebest.py` 분석용.
