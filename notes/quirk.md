# quirk: 숨은 정수 해독 (특정 퍼즐을 겨냥한 방법)

작성: 2026-11-24. 코드는 `solvers/quirk/`, 결과는 `results/quirk.csv`, 진행 상태는 [quirk.status.md](quirk.status.md).

## 1. 한 줄 요약

구조형 퍼즐의 목표값은 `t = k·a·b + r` 꼴이다. a, b 는 퍼즐마다 숨어 있는 정수 몇 개이고 k, r 은 작다. 이 정수들을 목표값만 보고 복원해서 프로그램 맨 앞에 먼저 만들어 두면, 허브(a·b) 하나가 명령 1개가 되어 퍼즐당 10~30개가 줄어든다.

## 2. 근거

- scored_0006 (시작값 16, 29, 33, 목표 32개): 숨은 정수 261389, 327190, 571027, 835418 로 32개 목표가 전부 설명된다. 예: `68324209308 = 261389² − 13`, `2966181729887851 = 15876·327190·571027 − 29`. 공개 조사 노트(`research_notes/Elf Calculator 미시도 방법론 조사/competition_intelligence.md` 116행)에 적힌 사례를 직접 다시 계산해 확인했다.
- k 는 1부터 7만까지, r 은 대부분 수백 이하다. r 이 큰 목표는 `k2·(k1·a·b + r1) + r2` 처럼 한 번 더 겹친 것이다(예: `15·a² − 1815 = 15·(a² − 121)`).
- practice 가족별로 해독되는 퍼즐 수 (`decode_practice.py`, 엄격한 1차 해독기 기준): shared 43/51, mixed 22/48, multiplicative 17/40, independent 0/45, tiny 0/16.
  - independent 에서 0개라는 것은 오검출이 없다는 뜻이다.
  - multiplicative 는 정수가 작고(수백) 인수 여러 개의 곱이라 이 모형이 잘 맞지 않는다. 걸린 17개도 설명되는 목표가 퍼즐당 3개쯤이다.

## 3. 해독기

| 파일 | 하는 일 |
|---|---|
| `decode.py` + `basescan.cpp` | d 를 64 부터 2^24 까지 전부 훑어 `\|t mod± d\| ≤ min(d/512, 1024)` 인 목표가 3개 이상인 d 를 후보로 모은다. 같은 `(t, r)` 에서 `d·d' \| t − r` 인 후보 쌍만 설명으로 인정하고, 설명되는 목표가 가장 많은 쌍에서 출발해 정수를 하나씩 더한다. 퍼즐당 약 1.6초 |
| `decode2.py` | 1차 결과를 넓힌다. 2^24 넘는 정수는 근사 제곱(`t ≈ k·s²`)으로, 새 정수는 `(t − r)/a` 몫들의 공약수로 찾는다. 설명 기준은 `\|r\| ≤ a·b / 2^13` |
| `decode3.py` + `pairscan.cpp` | 작은 정수(2^8~2^20)용. `t = k·a·b + r` (k ≤ 8, \|r\| ≤ 128)인 `(a, b)` 를 전부 나열한 뒤, 서로 다른 목표 3개 이상에서 살아 있는 상대와 짝이 되는 정수만 반복해서 남긴다 |
| `decode4.py` + `basescan2.cpp` | 1차가 빈손일 때 허용폭을 넓힌 훑기 (`R = min(d/128, 4096)`, 적중 4개 이상) |
| `decode_any.py` | 위를 묶은 것. `decode_all.py` 가 전체 퍼즐에 돌려 JSON 으로 저장한다 |
| `decode2.canonicalize` | 정수의 배율 정리. b 를 2, 3, 5, 7 로 곱하거나 나눠 설명되는 목표가 늘거나 k 가 작아지면 바꾼다. practice_0019: [46367, 788342, 274570] → [92734, 394171, 549140], 설명 25 → 28. 채점 퍼즐 150개에서 정수가 바뀌고 설명되는 목표가 274개 늘었다 |
| `decode6.py` | 허브가 2^24 미만인 작은 정수용. 정수를 점, 설명을 변으로 본 그래프에서 무게(놀라움 비트 합)가 큰 2~3점 구조를 찾아 넓힌다. 통계적으로는 우연과 구분이 안 되는 경우가 많아, 씨앗으로 넣어 실제로 짧아진 것만 남긴다 |

오검출을 막는 조건 (없으면 independent 45개 중 42개가 잘못 해독됐다):
- 출발 쌍은 목표 2개 이상을 설명해야 한다.
- 설명에 두 번 이상 쓰이는 정수만 남긴다.
- 허브 `a·b` 가 2^24 미만인 설명은 버린다(작은 허브는 우연히 나누어떨어진다).

## 4. 해독 결과를 프로그램으로 바꾸기

## 6. 안 통한 것

- **무작위 목표의 정확한 최소 비용 탐색** (`oracle.cpp`, `oracle_exp2.py`). 실제 레지스터 풀(48개 값)에서 목표 하나를 따로 만드는 최소 명령 수를 명령 6개까지 전수 탐색으로 구했다. scored_0001 (50비트 무작위 목표 32개, best 241개 = 목표당 7.53):
  - 목표 10개를 만든 시점의 풀에서 남은 22개 목표는 전부 7개 이상이 든다. 그런데 프로그램은 그 뒤로 목표당 6.55개만 쓴다.
  - 목표 20개 시점에서는 남은 12개가 1, 2, 4, 4, 6, 6개와 7개 이상 6개인데, 프로그램은 목표당 4.92개만 쓴다.
  - 즉 지금 해는 여러 목표가 중간값을 나눠 쓰기 때문에 "목표 하나씩 최적으로 만들기"보다 이미 짧다. 목표별 탐색을 더 깊게 해도 얻을 것이 없다. 무작위형에서 줄이려면 공유할 중간값을 설계해야 하는데, 구조가 없어서 겨냥할 방법을 못 찾았다.

- 연분수로 목표 쌍의 `q·t1 − p·t2 = r` 찾기(`cf.py`): 허브가 같은 쌍은 잡지만 정수 하나만 공유하는 쌍은 못 잡는다.
- 얕은 닫힘 값으로 `t = k·h + e` 투표(`forensic.py`): 작은 h 에서 우연 일치가 너무 많다.
- 작은 정수 해독에서 허용폭을 키우기(k ≤ 32, \|r\| ≤ 512): 2,000 이하의 정수가 우연히 다 살아남아 가려낼 수 없다. practice_0004 (669 × 88224, 오프셋 1008 까지)는 아직 해독하지 못한다.
- 무작위형(independent) 퍼즐: 목표가 `[10^(n−1), 10^n)` 균등 난수로 보이고 숨은 정수가 없다. 목표 6,539개의 2, 3, 5, 7, 11, 13 배수 비율과 소수 비율이 균등 난수의 기대값과 같다. `value_limit` 이 최대 목표와 붙어 있는 것은 10^18 상한 때문이다.
- 허브 하나짜리 군집의 허브를 씨앗으로(`decode7.py`: 연분수 관계로 군집을 묶고 오프셋 비트 합이 최소인 허브를 고름): scored_0823 등 6개 퍼즐 모두 best 보다 7~28개 길다. 이런 군집은 lns 가 스스로 찾는다.
- 해독 퍼즐을 씨앗·설정을 바꿔 처음부터 다시 구성(`run5.py`)하는 것은 구조를 더 찾는 효과는 없고 출발점을 바꾸는 효과만 있다: 174개 퍼즐에서 합 107 (퍼즐당 0.6). scored_0909 는 원본 144 → 다듬어 122 로 best 116 을 못 넘었다.
- multiplicative 가족: 목표가 얕은 식 여러 개의 곱이다(scored_0064 의 59 = 26 + 33 이 목표 6개의 인수). 목표별 정확한 최소 비용은 평균 약 4.1 인데 lns 가 다듬은 프로그램은 공유로 2.86 이라(scored_0199) 구조를 따라 만드는 쪽이 오히려 길다.
- 퍼즐 사이 재사용: 큰 목표값이 두 퍼즐에 나오는 경우 0, 연습 퍼즐과 같은 채점 퍼즐 0.

## 7. 남은 것과 다시 쓰는 법

- mixed: 목표값의 정확히 절반쯤(45% 이상)이 한 자릿수 구간에 몰려 있고, 그 절반은 균등 난수다(맨 앞 자리 분포가 평평하다: 1이 0.143, 9가 0.104). 나머지 절반이 구조형이다(48/48).
- shared, multiplicative: 크기가 퍼져 있다(85/91, 6개는 mixed 로 잘못 분류).

채점 퍼즐: indep 247개(best 합 48,913, 목표당 7.14), mixed 304개(41,028, 5.46), 구조형 433개(44,309, 3.55), tiny 16개. 무작위 목표는 indep 6,848 + mixed 절반 약 3,900 으로, 총점의 절반 이상이 구조가 없는 목표값에 든다.

### 9.3 큰 오프셋 정수 해독 (`decode8.py`): 새 발견

해독기 1차(`decode.py`)와 `decode2.expand_once` 는 `|r| ≤ a/128` 처럼 정수에 비례하는 오프셋만 본다. 실제 생성기의 오프셋은 정수 크기와 상관없이 절대값 수천이라, 16~17비트 정수가 `t = a·c + r`(r 이 수천)로 쓰이면 놓친다.

- 예: practice_0145 의 `3858987186 = 70932·54404 + 2658`, `27655787728 = 508341·54404 + 3964`, `957028164930 = 248·70932·54404 + 1986`. 54404 는 어떤 해독기도 못 찾았다.
- 방법: 아는 정수 a(와 허브 a·b)로 나눈 몫 `q = round(t/a)` 를 `|r| ≤ 16384`(절대)일 때 모으고, 서로 다른 목표의 몫끼리 gcd ≥ 1024 를 후보로 삼는다. 검증은 엄격한 설명(`|r| ≤ 8192`, `|r| ≤ 허브/2^16`, k ≤ 2^17)으로 하고, 새 정수가 서로 다른 (k, a, b) 묶음 2개 이상을 새로 설명해야 받는다(거의 같은 목표 쌍은 한 묶음으로 센다).
- 연습 퍼즐: shared 설명 목표 717 → 835 (40개 중 16개에 정수가 더해짐), mixed 216 → 237. practice_0152 12 → 27/28, practice_0185 3 → 19/30.
- 채점 퍼즐(해독된 532개): 180개 퍼즐에 정수 287개가 더해졌고 설명 목표가 6,593 → 7,233.
- 오검출: 무작위형 247개에 다른 퍼즐의 정수를 넣고 같은 절차를 돌리면 16개 퍼즐에 18개(퍼즐의 6.5%). 구조형 퍼즐에 틀린 정수를 넣으면 211개 퍼즐에서 정수가 "찾아지는데", 이것은 실제 허브 H 를 틀린 정수 w 로 나눈 근사 `c ≈ H/w` 다(예: scored_0006 에서 `143979574·594 ≈ 261389·327190`). 진짜 정수로 시작하면 이 꼴은 이미 설명된 목표라 받지 않는다.

### 9.4 그 밖에 잰 구조

- 설명 안 되는 구조형 목표값은 아는 정수의 배수 근처가 대조군보다 40배 많다(오프셋 ≤ a/4096: 6.9% 대 0.17%). 9.3 의 해독이 이것의 일부를 설명한다.
- 겹친 꼴 `t = k·(h + c) + r2` (|r2| ≤ 16): k ≥ 16 이고 |r| ≥ 4k 인 목표 1,567개 중 1,107개(우연 기대 650). 겹침은 실제로 있지만 안쪽 값 `h + c` 를 두 목표가 함께 쓰는 경우는 1,563개 중 4쌍뿐이라 씨앗으로 쓸 값이 없다. 접음.
- 작은 숨은 정수 m: 해독된 퍼즐의 k 와 r 값 가운데 m(200~3,000)의 배수 ±4 인 것이 평균 6.16개(값을 퍼즐 사이에서 섞은 대조군 3.54, 최대 8). scored_0705 는 m = 555 로 38개 중 18개. 대부분은 best 프로그램에 m 이 이미 있다(lns 가 스스로 찾는다).
